# 0002: 节点默认出站与屏蔽回国规则解耦及兼容性演进

明确“节点默认出站”的产品语义，将海外白名单放行与普通外网流量绑定到节点各自的默认出站（默认采用 IPv4 优先）；采用“节点独立规则块”架构确保多节点与中转隔离，并在节点出站方式变更时实现原子更新与配置回滚。

## Context

在先前的实现中，白名单放行规则被硬编码为强制走本机的 `direct` 出站。当用户为节点配置了前置代理出口（如 Shadowsocks / VLESS）后，白名单流量会脱离用户期望的代理链路而从 VPS 本机直连泄漏。

此外还存在以下深层问题：
1. **中转隔离缺失**：旧的阻断和嗅探规则缺乏精准的入站作用域限定，可能影响 TCP/UDP 端口中转（Relay）业务（如中转到国内目标被阻断，或纯 TCP 流量被嗅探引入延迟）。
2. **特殊分流时序缺陷**：在未开启屏蔽回国时，代理出站规则被错误置于用户自定义规则之前，导致用户手写的特殊分流（如 YouTube → 特殊出站）无法命中。
3. **节点耦合严重**：规则按功能全局分层，使得单节点出站方式修改或删除时，无法原子清理对应的白名单与出站规则。
4. **内核弃用警告**：依赖已被弃用的 `download_detour` 和 legacy `type: "block"` 出站。

## Considered Options

- **规则组织形态**：全局功能分层混合 vs 节点独立规则块（Per-node Rule Block）
  - 选择节点独立规则块：在顶层统一嗅探和用户自定义特殊分流之后，为每个受管代理节点建立 `[白名单 -> 阻断 -> 默认出站]` 的闭环单元。节点出站修改或删除只需局部重写该单元，多节点互不干扰。
- **入站作用域限定**：全局无限制 vs 精确绑定受管节点入站（Inbound-scoped）
  - 选择精确绑定受管代理节点：嗅探和阻断严格限定在受管节点的 `inbound` 列表内，确保端口中转（Relay）等其他原生业务完全隔离不受影响。
- **嗅探生命周期**：随屏蔽开关启闭 vs 受管节点常态化路由嗅探
  - 选择常态化路由嗅探：无论是否开启屏蔽回国，受管节点始终启用路由层 `action: "sniff"`，保障用户自定义域名分流在任何状态下稳定工作。
- **基准出站模式**：新增“系统默认直连”模式 vs 复用既有“IPv4 优先”
  - 选择复用既有“IPv4 优先”：sing-box 原生 `prefer_ipv4` 策略天然具备“优先 IPv4、无 IPv4 则自动回落至 IPv6”的能力，完全满足服务器出网需求。无需额外引入第 7 个出站模式概念，新节点与历史老节点统一平滑默认采用“IPv4 优先”。
- **内核现代化规范**：
  - 阻断机制：淘汰 legacy `type: "block"` 出站，全面切换为现代路由动作 `action: "reject"`。
  - 规则集下载：淘汰 `download_detour: "direct"`，采用全局顶层 `http_clients` 规范。

## Consequences

- 节点出站变更时，其关联的白名单规则与外网路由规则同步原子更新。
- 历史老节点在升级后无感初始化为“IPv4 优先”，规则链路闭环且受安全防护，不增加用户心智负担。
- 用户在 config.json 中自定义的特殊分流规则（如特定流媒体走专用出口）始终拥有最高分流优先级。
- 端口中转（Relay）流量彻底免受屏蔽回国规则和嗅探的误伤。
- 配置文件完全消除 sing-box 1.14+ 的弃用警告。
