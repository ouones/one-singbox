# 节点与端口转发备注设计

**状态：** 已确认设计（Approved design）  
**日期：** 2026-11-24

## 背景与目标

在日常使用 `one-singbox` 管理多个代理节点和端口转发（Relay）时，仅凭配置文件名或目标地址端口难以直观回想起每条配置对应的落地节点指向、人工调整记录及节点特征。

本设计旨在为**代理节点**与**端口转发**提供统一的人工“备注”能力，并在节点详情页同步展示系统实际生效的“出口方式”，使维护者可以在终端内一眼识别每条配置的用途、人工改动记录与实际出站状态。

## 术语与边界

- **独立于节点名称**：备注（`note`）是仅在 `one-singbox` 终端管理工具内部可见的单行纯文本标注，与面向客户端分享链接的“节点名称”完全解耦，绝不写入分享链接、二维码或 Surge 配置。
- **纯手动维护**：备注内容 100% 由用户手动填写、修改或清空，系统不会在修改出站或变更配置时自动生成、追加或覆盖备注。
- **文案规范**：用户可见文案统一使用 **端口转发**（不使用“端口中转”）与 **one-singbox**（不使用“管理面板”），与 [GLOSSARY.md](../../../GLOSSARY.md) 保持一致。

## 展示规范

- **节点选择列表**（查看 / 修改 / 删除前的节点选择列表）：
  - 有备注时显示为：`VLESS-REALITY-12345.json  [备注: 摘要...]`（超过约 30 字符时截断并追加 `...`）；
  - 无备注时保持原样，不展示空占位符；
  - 列表内不额外拼接自定义节点名称，保持单行简洁对齐。
- **节点详情页（`info`）**：
  - 始终展示只读的 **出口方式** 行（反映系统当前实际生效的出站模式，例如 `IPv4 优先`、`Shadowsocks 出口 (...)`）；
  - 有备注时展示完整的 **备注** 行；无备注时省略该行。
- **端口转发列表（`relay list`）**：
  - 有备注时显示为：`监听端口 X -> 目标 Y:Z (TCP/UDP)  [备注: 摘要...]`（超过约 30 字符时截断并追加 `...`）；
  - 无备注时保持原样，不展示空占位符。
- **端口转发详情页（`relay info` 及 `relay add` 添加成功回显）**：
  - 有备注时展示完整 `备注: <内容>`；
  - 无备注时省略该行。

## 交互入口与编辑规则

- **创建时可选**：
  - 交互式添加节点（位于“输入节点名称”之后）与交互式添加端口转发（位于“输入目标端口”之后）新增一步可选提示：`输入备注 (可选，直接回车跳过):`；
  - 命令行非交互方式创建节点不增加交互打断。
- **事后编辑入口**：
  - 节点：`节点管理 → 修改 → 备注`；
  - 端口转发：菜单项调整为 `添加 / 列表 / 查看 / 备注 / 删除`（新增一层直达的“备注”菜单项，不套二级菜单）。
- **交互编辑规则**：
  - 进入编辑时先显示 `当前备注: <内容>`（若无备注则显示 `当前备注: (无)`），随后提示：`请输入新备注 (直接回车保持不变，输入 - 或 clear 清空):`；
  - 直接回车：保持原备注不变（防止误操作清空）；
  - 单独输入 `-` 或 `clear`：清空当前备注；
  - 输入其他单行文本：去除首尾空白后覆盖保存。

## CLI 规范

后续实现时需同步更新 `sb help` 帮助文案：

- **节点**：
  - `sb change <节点> note [备注内容 | --clear]`
  - 短命令：`sb note <节点> [备注内容 | --clear]`
  - 省略 `[备注内容 | --clear]` 时进入交互编辑；传入备注内容时支持含空格参数；传入 `--clear` 时直接清空。
- **端口转发**：
  - `sb relay note [监听端口] [备注内容 | --clear]`（省略备注参数时进入交互编辑；传入 `--clear` 时直接清空）；
  - `sb relay add [监听端口] [目标地址] [目标端口] [备注]`（第 4 参数为可选备注）。

## 生命周期与副作用边界

- **改配置保留**：节点修改端口或协议导致配置文件名变更时，备注随元数据自动迁移保留；切换节点出站方式时保留原备注不动。
- **删除清理**：删除节点或删除端口转发时，同步删除对应元数据文件，避免之后使用同一监听端口新建端口转发时意外继承旧备注。
- **零断流**：新增、修改或清空备注仅读写管理工具元数据，不修改 sing-box 运行时配置，不触发 sing-box 重启。

## 存储与 ADR 说明

- **元数据存储**：复用项目既有的 `.quan-meta/<配置>.meta.json` sidecar 元数据机制，在 JSON 对象中新增 `note` 键；端口转发对应 `.quan-meta/relay-<port>.json.meta.json`。
- **ADR 评估**：本方案属于既有 `.quan-meta` 机制的直接延伸，改动边界清晰、完全可逆且不存在违反直觉的架构权衡，按项目 ADR 准则无需单独新增 ADR。
